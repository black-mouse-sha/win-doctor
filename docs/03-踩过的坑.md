# 🕳️ 踩过的坑

这些都是真踩过的，不是编的。每一条都标了**症状**和**怎么发现**，方便你对照自己的情况。

---

## 坑 1：页面文件锁死 2 GB，还以为是「优化」

**症状**

开个 Cursor 就崩，日志里写 `renderer process gone (reason: oom)`。

**怎么发现的**

查页面文件配置：

```powershell
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management' -Name PagingFiles).PagingFiles
```

输出：

```
C:\pagefile.sys 2048 2048
```

初始值和最大值一样，都是 2048 —— **这是手动设的固定值，Windows 自己不会这么配。**

**为什么会变成这样**

网上到处是这种教程：「虚拟内存设成 2 G，C 盘立刻多出 10 G 空间」。

那条建议是 2010 年代给 4 GB 内存的老机器写的应急招。放到 16 GB 的机器上：

```
物理内存 16 GB + 页面文件 2 GB = 系统只敢承诺 18 GB
内存吃到 14 GB → 只剩 4 GB 周转 → 一挤就杀程序
```

**怎么改**

见 [modules/03-页面文件.md](../modules/03-页面文件.md)。核心是改成动态，并且别只放在系统盘。

## 坑 2：23 GB 的僵尸页面文件，躺了一年

**症状**

F 盘「明明还有 362 GB」，但总觉得少了一块。任务管理器里提交上限也对不上。

**怎么发现的**

```powershell
cmd /c "dir F:\pagefile.sys /a"
```

输出：

```
2025/11/13  16:55    24,696,061,952 pagefile.sys
```

**一个 23 GB 的文件，创建于一年前。**

但再看系统实际在用的：

```powershell
Get-CimInstance Win32_PageFileUsage
```

只有一个：`C:\pagefile.sys`。

**也就是说：文件在那儿，系统根本没加载它。**

**为什么会这样**

时间线大概是这样：

```
2025 年某天   设过 F 盘页面文件 → 生效，生成 23 GB 文件
某次操作       配置被清掉（系统更新 / 优化软件 / 手动改过）
之后           文件还在（Windows 不自动删），但系统不再加载
结果           白占 23 GB 硬盘，一天没工作过
```

**教训**

`dir` 能看到文件 ≠ 系统在用。**判断标准只有一个：`Win32_PageFileUsage` 里有没有它。**

## 坑 3：删了旧文件，重启后还是没生效 ⭐ 最新

这是本次排查最有价值的一个坑，网上资料很少。

**背景**

F 盘有个 23 GB 的老 `pagefile.sys`，配置里写的是 `16384 32768`（16 GB 初始）。

按常理：改完配置 → 重启 → 系统应该按新配置重建文件。

**实际结果**

重启后：

```powershell
Get-CimInstance Win32_PageFileUsage
```

```
Name              AllocatedBaseSize
C:\pagefile.sys                 4096
```

**F 盘那 16 GB 完全没出现。** 提交上限还是 19.69 GB（15.69 物理 + 4 C 盘）。

而 C 盘的页面文件从 2048 变成了 4096 —— 说明**配置确实生效了，只是 F 盘被跳过了**。

**原因**

F 盘上那个旧文件是 23 GB，配置要求 16 GB 初始。系统启动时尝试挂载，大小对不上、或者文件头信息不匹配，挂载失败 → **静默跳过，不报错，不写日志**。

**修复**

```powershell
# 管理员权限
takeown /f F:\pagefile.sys /a
icacls F:\pagefile.sys /grant administrators:F
Remove-Item F:\pagefile.sys -Force
```

删掉旧文件，**再重启一次**，系统会按配置重新生成干净的。

**教训**

> 改页面文件配置之后，如果发现某个盘没生效，先去看看那个盘上的旧 `pagefile.sys` 还在不在。
> 在的话，删掉它再重启。

这个坑特别隐蔽，因为 Windows **完全不报错**。你只会看到提交上限对不上。

## 坑 4：WMI 创建页面文件设置，静默失败

**症状**

脚本里跑 `New-CimInstance -ClassName Win32_PageFileSetting`，退出码 0，日志显示「新建成功」。

但去注册表一看：

```
PagingFiles = C:\pagefile.sys 4096 8192
```

**只有一条，新加的那条根本没写进去。**

**原因**

`Win32_PageFileSetting` 这个 WMI 类在某些情况下（尤其是给非系统盘新建）会静默失败，不抛异常、不返回错误。

**正确做法**

**别用 WMI，直接写注册表：**

```powershell
# 管理员权限
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management" /v PagingFiles /t REG_MULTI_SZ /d "C:\pagefile.sys 4096 8192\0F:\pagefile.sys 16384 32768" /f
```

格式：`盘符:\pagefile.sys 初始MB 最大MB`，多条之间用 `\0` 分隔（这是 REG_MULTI_SZ 的分隔符）。

**验证：**

```powershell
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management' -Name PagingFiles).PagingFiles
```

应该列出每一行。

**另一个坑**：改完注册表，`Win32_PageFileSetting` 可能**不立刻反映**新值。别被吓到，重启后就对了。

## 坑 5：PowerShell 脚本中文全乱码，引号都崩了

**症状**

写了个带中文输出的 `.ps1`，语法检查报一堆莫名其妙的错：

```
表达式或语句中包含意外的标记"}"

字符串缺少终止符: "
```

**原因**

文件是 **UTF-8 无 BOM**，而 **Windows PowerShell 5.1 默认按 ANSI（GBK）读文件**。

中文被读成乱码之后，里面的全角括号、引号会破坏语法解析 —— 看起来像语法错误，其实是编码错误。

**修复**

存成 **UTF-8 with BOM**：

```powershell
$content = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
$utf8bom = New-Object System.Text.UTF8Encoding($true)
[System.IO.File]::WriteAllText($path, $content, $utf8bom)
```

或者干脆在脚本开头加：

```powershell
chcp 65001 > $null
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

**教训**

写给 Windows 用户跑的 PowerShell 脚本，**一律存 UTF-8 BOM**，省得别人拿去一跑全是乱码。

## 坑 6：把企业零信任 VPN 认成网吧管理软件

**症状**

看到服务名叫 `F8iCloudServiceBeta`、`F8VisitorSer`，发布者是「福莱特信息技术有限公司」。

第一反应：这不是网吧管理系统吗？

**差点误删。**

**真相**

```powershell
Get-ItemProperty HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\* |
  Where-Object { $_.DisplayName -match '零信任' }
```

```
DisplayName    : 浙江移动零信任网络安全接入系统
Publisher      : 福莱特信息技术有限公司
UninstallString: C:\Program Files (x86)\F8 iCloud Platform Beta\uninst.exe
```

**F8 = 浙江移动的零信任 VPN 客户端**，是员工远程接入单位内网用的。

`iCloud`、`Visitor` 这些词只是产品线命名，跟网吧半点关系没有。

**教训**

> **查服务归属，别看服务名，看发布者和安装项。**
>
> 而且卸载企业安全软件之前，一定要问：「这电脑是公司发的吗？」

## 坑 7：「手动」启动了，但软件连不上

**症状**

把 MySQL 服务从「自动」改成「手动」，省内存。

结果打开 Navicat，连接失败。

**原因**

**Windows 服务不会因为某个程序去连接它而自动启动。**

我以为「有程序要用它，它就会起来」——这个理解只对*服务依赖服务*的情况成立。普通程序连接端口，不会触发服务启动。

**怎么判断该留自动还是改手动**

| 类型 | 例子 | 建议 |
|---|---|---|
| 软件一开就必需 | MySQL、SQL Server、许可证服务 | **留自动** |
| 只在特定操作时需要 | VMware NAT/DHCP、USB 直通 | 可改手动 |
| 后台更新器 | QQ浏览器、Adobe、Edge | 改手动 |
| 纯装饰 | 罗技灯效、壁纸引擎 | 改手动 |

**如果已经改了手动，怎么补救**

```powershell
# 临时启动
net start MySQL80

# 或者改回自动
Set-Service -Name MySQL80 -StartupType Automatic
Start-Service -Name MySQL80
```

## 坑 8：以为「缓存小」导致 AI 慢

**症状**

跑 `deepseek-r1:1.5b`（1.1 GB 的小模型），回答慢得像挤牙膏。

第一反应：「是不是我电脑缓存太小？」

**真相**

模型推理**不吃缓存**。它吃的是：

- 显存带宽（权重搬运速度）
- GPU 算力（矩阵乘）
- 上下文长度

**1.5 B 的模型在 RTX 4060 上应该是 100+ 字/秒，快到你觉得「怎么这么快就完了」。**

如果慢，九成是：**它根本没在用显卡，退回 CPU 硬算。**

**怎么确认（不用测，看一眼就行）**

跑模型的时候打开任务管理器 → 性能 → GPU：

```
GPU 60~90%   → 正常在用显卡
GPU 0~5%     → 确诊，在用 CPU
```

**CPU 和 GPU 跑同一模型的差距**

```
RTX 4060 显卡     40~70 字/秒
i7-12650H 纯 CPU   2~3 字/秒     ← 慢 20 倍
```

## 坑 9：Edge 自启删了又回来

**症状**

把 `MicrosoftEdgeAutoLaunch_xxx` 从注册表 Run 里删了。

第二天开机，它又在那儿了。

**原因**

Edge 启动时会检查自己的启动设置，觉得「我应该开机启动」，就把注册表项**写回去了**。

**彻底关闭的办法**

```
Edge 设置 → 系统和性能 → 启动时
  → 关掉「系统启动时自动启动 Microsoft Edge」
```

或者在组策略里禁掉（专业版）：

```
计算机配置 → 管理模板 → Microsoft Edge
  → 「启动时加载 Microsoft Edge」→ 已禁用
```

**教训**

删注册表只能治一时，软件自己会写回来。**要改配置就改软件自己的设置。**

## 坑 10：任务计划里的自启，注册表里看不到

**症状**

把注册表 Run 和启动文件夹都清干净了，开机还是有一堆东西自己起来。

**原因**

**自启有三个地方，不是两个：**

```
① 注册表 HKCU/HKLM Run          ← 大家都会查
② 启动文件夹                      ← 部分人会查
③ 任务计划程序（登录/开机触发）    ← 最容易漏
```

查任务计划：

```powershell
Get-ScheduledTask | Where-Object {
  $_.State -ne 'Disabled' -and
  ($_.Triggers | Where-Object { $_.CimClass.CimClassName -match 'Logon|Boot' })
} | ForEach-Object {
  $exe = ($_.Actions | Select-Object -First 1).Execute
  "{0,-50} {1}" -f $_.TaskName, $exe
}
```

这次就查出了 OneDrive 的两个启动任务、QQ 浏览器更新、WPS 更新、Adobe 更新等等。

**注意**：这里面**大部分是 Windows 自己的系统维护**（`DirectXDatabaseUpdater`、`Device User`、`Proxy`、`Monitoring`），别动。

只处理那些 `Execute` 指向非 Windows 目录的。

## 坑 11：改了服务启动方式，内存没释放

**症状**

把一堆服务改成「手动」，看着配置生效了。

但可用内存一点没变。

**原因**

**改启动方式只影响「下次开机还起不起」，不会停掉正在运行的。**

```
Set-Service -StartupType Manual   →  下次开机不启动
Stop-Service                      →  现在就停
```

两个都得做。

**正确顺序**

```powershell
# 1. 先改启动方式
Set-Service -Name "VMware NAT Service" -StartupType Manual

# 2. 再停掉当前的
Stop-Service -Name "VMware NAT Service" -Force
```

这次实测：11 个服务停掉，可用内存从 5.19 GB → 6.13 GB，**释放 0.94 GB**。
